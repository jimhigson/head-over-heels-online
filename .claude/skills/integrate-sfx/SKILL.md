description: Integrate exported sounds from the sfx manager into the codebase's sound system
---

Integrate new sounds from the sfx export at `src/sounds/exported/sfx.ts` into the main sound system.

## Steps

1. Read `src/sounds/exported/sfx.ts` to see what sounds are currently exported.

2. Read `src/sound/soundUrls.ts` to see what sounds are already integrated.

3. Compare the two: find sounds in the sfx export that are NOT yet in `soundUrls.ts` (ignoring any that are already there from a previous integration).

4. **Before proceeding, list the new sound files to the user and ask for confirmation.** Show each sound name and ask if the list is correct.

5. After confirmation, for each new sound:
   a. Copy the mp3 file from `src/sounds/exported/sfx/` to `sounds/` (the project root sounds directory)
   b. Add an import line in `src/sound/soundUrls.ts` following the pattern: `import <name>SoundUrl from "../../sounds/<name>.mp3";`
   c. Add an entry in the `soundUrls` object: `<name>: <name>SoundUrl,`

6. Keep the imports sorted alphabetically (the linter will do this, but aim for it).

7. Keep the `soundUrls` object keys in alphabetical order (the `roomEntry.*` spread stays at the end).

8. Update `src/sounds/exported/sfx.ts`: remove the entries that were integrated, and remove their corresponding import lines. If all entries were integrated, the `sfx` object should be empty (`export const sfx = {};`).

9. If `sfx` is now empty and nothing imports it, remove the `...sfx` spread from `soundUrls.ts` and its import line.

## Important notes

- The sfx export file (`src/sounds/exported/sfx.ts`) is auto-generated by an external audio management tool. Never modify the mp3 files in `src/sounds/exported/sfx/` — only copy them.
- Sound IDs (the keys in `soundUrls`) must use camelCase.
- The `soundUrls` object must NOT use a spread of the sfx object once all sounds are integrated — each sound gets its own direct import and entry.
